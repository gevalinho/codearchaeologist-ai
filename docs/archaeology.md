# Repository intelligence engine

Run locally with `ARCHAEOLOGY_REPO_ROOT=/absolute/path/to/repository npm run archaeology:scan`. The command reads only application PHP and JavaScript plus named application scripts in `assets/js`. It writes `.local-archaeology/graph-<snapshotId>-<runId>.json`, which is gitignored. It does not use the model provider or expose a route.

The version 1.0.0 graph has a content-derived snapshot ID, typed nodes and edges, relative source references, observed or inferred certainty, extraction method, deterministic order, warnings, and limits. Contents and absolute paths are omitted. The scanner uses deterministic patterns, not a PHP or JavaScript parser. It can miss multiline declarations and dynamic calls, and can mistake strings for code. Table references from SQL literals and recognized model calls are best effort. AngularJS registration ownership is best effort when one file contains several components. Domain labels reflect names only and do not establish reachability. Review source at the cited line before treating any relationship or risk as verified.

Flagship investigation: `Putdatacrtl::putScore` has guards for CA above 40 and exam score above 60, with writes to `result`. `Putdatacrtl::putPromotion` checks an active session, requires destination class and class operation, checks whether the student's session is the current one, compares current session start with prior session end, then updates and inserts `classes` membership. `Getdatactrl::getPromotion` and `getCollatedResultinput` read class and result data. The AngularJS `promotionCtr` posts to `index.php/reg/putpromotion` and fetches `index.php/gett/getpromotiondata`. This establishes the inspected path only; it does not show that promotion is universally independent of academic results. Possible missing negative-score validation or SQL query risks are hypotheses requiring manual review, never verified vulnerabilities.
