# Controlled public GitHub ingestion

The Repository Intelligence workspace can analyze a canonical `https://github.com/owner/repository` URL when its server operator enables this optional feature. The local browser directory scanner and graph JSON import still work without it.

## Run locally

1. Install and start Docker. Pull `node:22-bookworm-slim` in advance. The server checks that the daemon is reachable, reports a structured seccomp security option, and has a local image with a valid SHA-256 ID. It then runs two short, source-free probe containers: one baseline with `seccomp=unconfined` and one with `seccomp=builtin`. The scanner is available only when the built-in profile adds a verified seccomp filter. A daemon reporting `profile=unconfined` alone is never proof of enforcement. It does not pull images during a job.
2. Configure the GitHub App and durable session variables in [GitHub App setup](github-app.md). Set `ENABLE_GITHUB_INGESTION=1` in ignored `.env.local`. `GITHUB_APP_ORIGIN` must equal the browser origin.
3. Run `npm run dev` or `npm run build && npm run start`. Sign in through **Connect GitHub**, choose **New Investigation → Analyze GitHub Repository**, enter a public URL, and submit. The graph and manifest become downloadable when the job is ready.

The server process needs permission to use the Docker daemon. On the current development environment the Docker CLI is installed but daemon socket access is denied, so a GitHub job reports *Isolated scanner unavailable* before any repository fetch. The CLI scanner (`npm run archaeology -- --repo /absolute/path`) and browser directory scan remain available. Do not give a public web process broad Docker daemon access without a separate deployment security review; the daemon is a powerful host control surface.

## Trust boundaries and limits

- The browser sends a repository URL and an HttpOnly session cookie. The OAuth token stays encrypted in the server's private SQLite database and is never sent to the browser or scanner container. The server rechecks the token with GitHub before protected requests.
- The server accepts only canonical public GitHub URLs. It reads repository metadata, the default branch commit, and a recursive tree from `api.github.com`; it fetches selected regular source blobs from `raw.githubusercontent.com` at that commit. Both hosts are fixed, public DNS answers are checked and pinned for TLS connections, and redirects are rejected. No archive is downloaded or unpacked.
- Files are filtered with the same archaeology allowlist and exclusions as the CLI. Symlinks, submodules, sensitive files, dependencies, uploads, vendor, and unsupported files are not downloaded. Blob contents are checked against Git's SHA-1 identity from the selected tree. For a public repository with more than 300 eligible files, a deterministic round-robin across architectural roles and directories selects at most 300 files within the existing 2 MiB per-file and 12 MiB total-source budgets. Omitted eligible files are never downloaded. Private GitHub ingestion retains its existing fail-closed 300-file policy. GitHub reported repository size is informational. The complete commit tree must fit within the bounded 8 MiB tree response and 100,000-entry limit; truncated, malformed, or duplicate trees fail closed. The graph artifact and job summary record eligible, selected, omitted, analyzed, and excluded counts. Partial findings cannot rule out components or features in omitted files. Metadata/tree responses and each request have size and time limits. GitHub may rate-limit unauthenticated requests; that error is shown to the user.
- Public source blobs are fetched by a fixed four-worker pool. Each worker uses the existing pinned-DNS HTTPS request path; connections are not pooled. The aggregate byte budget is checked and reserved before writes, and acquisition aborts remaining requests and removes staged files after any failure. Job status exposes only rounded phase durations and selected/completed/failed blob counts. It does not include source content, credentials, request headers, or blob URLs. The whole-job deadline remains 90 seconds, so slow upstream responses can still cause a failed scan.
- The temporary source tree is scanned in a short-lived Docker container, using only trusted scanner files and the selected source tree as read-only mounts. It explicitly requests Docker's built-in seccomp profile and runs as a non-root user with no network, no capabilities, no privileged access, read-only root filesystem, 32 processes, 256 MiB RAM and swap, half a CPU, a 16 MiB temporary filesystem, and a 30-second command deadline. The entire job has a 90-second deadline. No repository script, installation, build, or lifecycle command runs. If seccomp enforcement, Docker, or cleanup cannot be confirmed, the job fails closed; there is no host-scanning fallback.
- One global scan lease is reserved in SQLite. Each authenticated user may start two scans per hour, and at most three jobs are retained for five minutes. Artifacts expire after five minutes. Active scanner controllers still live in their starting process; a separate worker remains a later deployment phase.
- Generated `graph.json` is parsed and validated before the job is ready. `manifest.json` includes source-derived counts, warnings, and coverage limitations. Graph findings remain source observations and inferences, not verified business behavior. A public GitHub repository is still untrusted input.

## EC2 deployment notes

Deploy behind an HTTPS reverse proxy and set `GITHUB_APP_ORIGIN` to that exact external origin. Configure private persistent `CODEARCH_DB_PATH`, `CODEARCH_ARTIFACT_DIR`, and `CODEARCH_STAGING_DIR`. Production scan creation is currently disabled until the separate scanner worker and secure handoff are implemented; see [worker boundary](isolated-scanner-worker.md). The production web process must have no Docker daemon access. Never mount the Docker socket into scanner containers.

## Manual browser acceptance

1. With GitHub ingestion disabled, submit a public URL and confirm a clear unavailable error. Confirm local directory scan and graph JSON import still work.
2. Enable the server and Docker, sign in with GitHub, select **Analyze GitHub Repository**, and enter a small public repository URL. Confirm each real status appears, then a graph loads automatically and the repository name, analyzed file/byte counts, modules, features, graph, and evidence inspector are available.
3. Download both artifacts. Reimport `graph.json`; check that the same snapshot and source references render.
4. Try a malformed URL, a private or missing repository, a URL with a query or extra path, and a repository beyond the limits. Confirm specific errors and no graph handoff.
5. Start a scan and cancel it during fetching or analysis. Confirm the job becomes cancelled, no artifacts are served, and a new job can start. Retry after an error.
6. Try an anonymous request, a logged-out session, a different user's job ID, and a cross-origin request; confirm none creates or exposes a job. Check server logs contain no source code or OAuth token. Check temporary scan directories are removed after success, failure, and cancellation.
