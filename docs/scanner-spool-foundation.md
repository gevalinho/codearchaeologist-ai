# B5.1 scanner spool foundation

`src/lib/github-ingestion/spool.ts` is an independent, synchronous filesystem handoff primitive. It is **not wired into job creation or Docker execution**. Production scanning remains disabled. The module accepts only UUID job and dispatch generation identifiers; it derives all paths from four configured, canonical absolute roots. The dispatch contains only IDs, a deadline, and the SHA-256 of a bounded manifest. The manifest contains only selected relative source paths, byte counts, and SHA-256 digests. Source bodies live only in the snapshot. No GitHub token, session record, SQLite database path, provider key, command, image, or mount path is serialized.

The web owner atomically publishes a complete snapshot directory and dispatch marker. The worker reads and hashes every declared file, rejects extra files and symlinks, then creates a private claim directory with exclusive `mkdir`. The worker can publish one bounded result envelope; the web side verifies its identity and hash. **The envelope is untrusted scanner output**: future integration must call `parseGraph`, verify job phase and generation in SQLite, recheck repository permission, and publish through `SqliteJobStore.publish`. A spool claim is not a database lease. Cancellation markers and active-generation checks reject stale work; they do not yet signal a running Docker process. Cleanup functions are explicit primitives and must only be called after terminal database reconciliation and worker shutdown.

## Required Unix permissions before integration

- Distinct `codearch-web` and `codearch-worker` UIDs. The web UID owns the session SQLite database and final artifacts in 0700 directories and 0600 files. The worker must have no path, group, ACL, or inherited file descriptor granting database access.
- A dedicated **inbox group** containing only web and worker. Web owns the inbox and snapshot roots, with mode 0750 or 2750, group inbox. Files must be 0640, and snapshot subdirectories 0750. A setgid root or explicit group assignment must ensure every nested source file has the inbox GID. The worker must have only group read/traverse rights; no write rights. World permissions must be zero.
- A separate **outbox group** containing only web and worker. Worker owns the outbox root (0750 or 2750), writes 0640 result files; web receives group read/traverse only. A worker-private 0700 claims root uses the worker's primary GID. Neither shared group may include unrelated service users.
- The process umask must permit the intended group-read bits (for example 0027). The module validates actual modes and owner/GID on each read. It does not create or repair root directories, change ownership, or grant ACLs.
- Root paths and ancestors must be canonical, and the filesystem must support same-filesystem atomic rename/link, durable `fsync`, and POSIX ownership semantics. The snapshot root must not include the SQLite database, final artifacts, secrets, or writable files from the web release. Mount and service-level permissions require verification on the target host.

An actor UID check prevents accidental use of writer operations under the wrong service account, but the **OS identity and filesystem permissions** are the real boundary. Same-UID automated tests exercise logic only; a later deployment test must run web and worker operations under separate UIDs and prove the worker cannot read web-owned secrets or connect to Docker from the web identity. A rootful Docker socket remains host-equivalent privilege; daemon isolation is a separate deployment prerequisite.

## Remaining integration work

Add a durable SQLite dispatch state and compare-and-swap lease, acquisition-to-spool adaptation, a worker runtime, cancellation polling and Docker abort, crash recovery, orphan sweeping, result validation/publication, and systemd units. Keep the production scan 503 guard until those checks pass. Do not interpret an existing spool result as a completed scan without server-side graph validation and authorization.
