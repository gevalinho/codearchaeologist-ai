# Local hackathon demo

Use Node.js 24 or newer for the operator CLI's built-in TypeScript transform. Keep `.env.local` private; it is Git-ignored. The following commands may use paid inference and must be invoked deliberately by the operator.

1. Set `INVESTIGATION_PROVIDER=baseten` with `BASETEN_API_KEY` in `.env.local`, or select `meta` with `MODEL_API_KEY`. The provider factory does not fall back to mock.
2. Start the local dashboard: `npm run dev`. Open `http://localhost:3000` to inspect the read-only `pricing.js` fixture.
3. To enable the dashboard's paid **Run AI investigation** button for a trusted local demo, set `ENABLE_LIVE_INVESTIGATION_HTTP=1` in `.env.local` and restart `npm run dev`. This performs source investigation only. The route is disabled by default; do not expose this opt-in mode to untrusted users.
4. Run isolated verification separately as the trusted operator: `npm run demo:report`. The script loads `.env.local`, makes live provider requests, runs only reviewed pricing cases in the existing hardened Docker sandbox, and writes `.local-demo/verification-report.json`. Docker, seccomp, and the local `node:22-bookworm-slim` image are needed for executable verification. If unavailable, findings are `BLOCKED`; the script never substitutes mock output.
5. Click **Load local report** in the dashboard. Inspect source citations and expand case details. The report banner distinguishes actual isolated execution from a run with no executed cases. If the model's wording does not exactly match a reviewed template, the rule remains `NOT_TESTED`.

If the operator command fails, set `CODEARCHAEOLOGIST_OPERATOR_DIAGNOSTICS=1` for the next deliberate run. It reports only fixed failure stages. For an investigation failure it also reports `INVENTORY`, `SELECT_FILES`, `CANDIDATE_RULES`, or `REVIEW_RULES` and a predefined category: `PROVIDER_CONFIG`, `PROVIDER_HTTP`, `PROVIDER_TIMEOUT`, `PROVIDER_NETWORK`, `PROVIDER_INCOMPLETE`, `PROVIDER_MALFORMED`, `EVIDENCE_VALIDATION`, `INVESTIGATION_TIMEOUT`, or `INVESTIGATION_INTERNAL`. A numeric HTTP status appears only when supplied by a typed provider error. No raw exception, prompt, response, key, or header is printed. Before any live retry, `npx vitest run tests/investigation.test.ts tests/demo.test.ts` checks the pipeline without a paid request.

For incomplete or malformed provider completions, the same opt-in diagnostic mode also prints an allowlisted finish reason (`stop`, `length`, `content_filter`, `tool_calls`, or `unknown`) and bounded integer output and reasoning token counts when available. A live `candidate_rules` completion ended with `length` after using all 1,500 output tokens, including 1,044 reasoning tokens. Phase 4.1 therefore allocates 3,000 tokens to that step while keeping `review_rules` and multi-file `select_files` at 1,500. The operator summary and dashboard show bounded totals for model calls, input tokens, output tokens, and reasoning tokens when every provider response supplies valid counts; missing counts display as unavailable. The strict response schema and verification rules are unchanged.

The investigation still has a 30-second overall deadline and a maximum of three model calls. Baseten's per-attempt limit is 12 seconds with up to two retries, so repeated slow attempts can exhaust that overall budget. The observed `INVESTIGATION` stage does not establish that this happened; leave both limits unchanged until the new category identifies the actual failure.

The trusted pricing inventory has exactly one eligible path, `pricing.js`. File selection is therefore deterministic and visible in the dashboard report metadata; candidate generation and review still use the live model, for two provider calls in a successful run. Multi-file inventories retain strict model selection. A prior `SELECT_FILES → EVIDENCE_VALIDATION` result establishes that the model's selection failed validation, but the exact returned value was not recorded and cannot be reconstructed from that category alone.

The local artifact is ignored by Git. The dashboard only reads and validates it; no HTTP route can start Docker. No demonstration report is bundled or fabricated.

To reverify a saved `NOT_EXECUTED` report without another model call, the trusted operator can run `npm run demo:reverify`. This command reads only `.local-demo/verification-report.json`, rejects symlinks and files over 128 KiB, checks the pinned fixture and evidence, and accepts only supported `NOT_TESTED` rules that match reviewed templates. It discards saved verification fields and runs the trusted cases through the existing Docker sandbox. It writes `.local-demo/verified-report.json` atomically, leaving the original report intact, and prints the actual status counts. The command does not load `.env.local` or instantiate an AI provider; it makes zero model calls. Docker execution can still return `FAILED` or `BLOCKED`, and only successful independent observations can produce `VERIFIED`. Do not run it as an HTTP request.

Ordinary `npx vitest run` and `npm test` exclude the paid smoke test. It has a separate `vitest.live.config.ts` and still requires its explicit opt-in environment flag. Production builds make no provider requests.
